# KinExport archive server

A local HTTP archive using Node.js 24's built-in SQLite support and streaming ZIP libraries. ImageMagick 7 is used to generate local image thumbnails. The root project supplies the recommended container setup; for local development run `npm ci`, then:

```sh
export KINEXPORT_TOKEN="replace-with-a-random-secret-of-at-least-32-characters"
npm start
```

By default the server listens on `127.0.0.1:8765` and writes `./data/kinexport.sqlite`. It accepts `HOST`, `PORT`, and `DATABASE_PATH`. Docker configures `HOST=0.0.0.0`, with the port published only on the host's loopback interface. A configured `KINEXPORT_TOKEN` (32+ characters) is required. Open the local server URL and enter the token to use the UI; it is retained in that browser tab's session storage until the tab closes or you lock the archive. Never put the token in a URL.

By default requests must use Host `localhost`, `127.0.0.1`, or `::1` to prevent DNS rebinding; `ALLOWED_HOSTS` is a comma-separated replacement list for unusual setups. Only add hostnames you control. The server does not grant cross-origin access to arbitrary websites; a browser extension background script may make requests using extension host permissions. Archive API responses require the token even on localhost. Keep the archive server bound to loopback; public deployment or exposing it to a LAN needs a separate security design.

See [operations and recovery](../docs/OPERATIONS.md) for day-to-day use, backup and restore, and troubleshooting.

## API

API endpoints use JSON except for the streamed archive and SQLite transfers. API requests require the header `Authorization: Bearer <token>`, except `GET /api/health` and one-use, cookie-authorized browser downloads. Health returns only `{ "status": "ok" }` and does not test a token; `POST /api/probe` with `{ "messages": [] }` is an authenticated connection check. No endpoints call Kindroid.

- `POST /api/accounts`: `{ "accountId": "...", "displayName": "...", "sourceTimestamp": "..." }`; the latter two fields are optional. Returns `{ "account": {...} }`. `GET /api/accounts` returns `{ "accounts": [...] }`.
- `POST /api/kins`: `{ "accountId": "...", "kinId": "...", "name": "...", "sourceTimestamp": "..." }`; name and source timestamp are optional and the account must already exist. Returns `{ "kin": {...} }`. `GET /api/kins?accountId=...` returns `{ "kins": [...] }`. IDs and timestamps are strings; source timestamps should use UTC ISO 8601 where known. Upserts preserve existing name fields when omitted. Only explicitly supported profile fields are stored; credentials and arbitrary unknown fields are rejected.
- `POST /api/kins/profile`: `{ "accountId": "...", "kinId": "...", "fields": { "ai_backstory": { "value": "...", "observedAt": "2026-01-01T00:00:00.000Z" } } }`. Each field requires `value`; `observedAt` is optional and means a verified page-cache observation time, not a source edit time. Dates must be UTC ISO 8601 strings. Returns field counts `{ "inserted", "updated", "unchanged", "historical" }`. `GET /api/kins/profile?accountId=...&kinId=...` returns `{ accountId, kinId, fields }`, where each field contains `value`, `observedAt` (null when unknown), `recordedAt` (local archive receipt time), an opaque `eventId`, and `history` entries with the same metadata. Both account and Kin must already exist.
- `POST /api/kins/journal`: `{ "accountId": "...", "kinId": "...", "entries": [{ "entryId": "...", "createdAt": "2026-01-01T00:00:00.000Z", "description": "...", "keywords": ["..."], "origin": "..." }] }`. Each batch accepts at most 500 entries. Keywords and origin are optional; omitted fields mean unknown, not deletion. Source IDs are scoped to the account and Kin. Differing observations are preserved as revisions because their edit order is not known. `GET /api/kins/journal?accountId=...&kinId=...&limit=50&offset=0` returns `{ accountId, kinId, entries, total, nextOffset }`, newest created date first. Limit defaults to 50 and is at most 100.

  Supported string fields are `ai_backstory`, `ai_memory`, `ai_directive`, `ai_example_message`, `developed_context_v1`, `developed_context_previous_v1`, `ai_name`, `voice_model`, `voice_call_directive`, `llm_flair`, `reasoning_effort`, `custom_avatar_description`, `custom_avatar_face_prompt`, `current_scene`, `default_room_bio`, `legacy_llm_model`, `legacy_selfies_model`, `video_model`, `auto_journal_day`, and `proactive_engine`. The separate `ai_backstory_plaintext`, `ai_memory_plaintext`, `ai_directive_plaintext`, `ai_example_message_plaintext`, and `current_scene_plaintext` fields contain observations of the visible profile editor; these may be unsaved edits. The original fields and their history are preserved separately. Number fields are `selected_voice`, `user_set_temperature`, `custom_avatar_fidelity`, and `custom_avatar_face_detail`. Boolean fields are `time_awareness`, `ai_reactions_enabled`, `avatar_is_anime`, `proactive_mode`, `live_tool_mode`, `disable_ltm_recall`, `disable_ltm_consolidate`, `has_cascade_memory`, `voice_call_use_fast_voice`, and `voice_call_unified_context`. Each may also be explicitly null. Strings can be empty and are capped at one million characters; numbers must be finite and bounded. Unknown fields, nested objects, credentials, URLs in background configuration, and proactive agendas are not collected as profile fields.

  An omitted field means unobserved and never clears stored data; explicit null, empty string, false, and zero remain distinct values. If two different values have source observation times, older or equal timestamps do not replace the current value; an undated value does not replace a dated value. Such conflicting observations are retained in history. Two undated values use receipt order because their source order is unknown. Identical observations do not create history. For archive imports, an older or equal recorded time also cannot replace the current value.
- `POST /api/probe`: `{ "accountId": "...", "kinId": "...", "messages": [{ "conversationId": "...", "messageId": "...", "fingerprint": "...", "captureSource": "cache" }] }`. Both scoped records must exist; each ID is a string and `messageId` and `captureSource` may be omitted. Returns `{ "results": [{ "status": "missing" | "unchanged" | "changed" }] }` in the same order.
- `POST /api/messages`: the same scope and list, with each item also requiring `content` and optionally accepting `sender`, `timestamp`, and `data`. `data` may contain only `persona` (string), `reactions` (bounded map of actor IDs to emoji strings, or array of strings or `{name?,emoji?,count?}`), `chatHistoryRecordId` (string), `senderAiId` (string), `reactionsRevision` (nonnegative integer), and `captureSource` (`"dom"` or `"cache"`). Returns `{ "inserted": n, "updated": n, "unchanged": n }`. The two batch endpoints accept up to 500 items per request. Client-provided fingerprints must include every change the caller wants saved. With a stable message ID, a changed fingerprint updates the message and retains the previous text as a revision; without an ID, the fingerprint is the fallback identity, so an edit cannot automatically be associated with the old message. Identity is scoped by account, Kin, conversation, and source ID, and IDs containing separators cannot collide.

When the same source ID has been seen in both the rendered DOM and the page's existing cache, cache content is authoritative: a cache observation upgrades a DOM observation, and a subsequent DOM observation cannot overwrite cache content. If the DOM text differs, it is retained as a revision tagged `data.captureSource: "dom"`; that rendering difference does not necessarily represent an edit. Older scoped records without a capture source are conservatively treated like cache records. Probe `captureSource` must match `data.captureSource` on ingestion for this rule to work correctly.
- `POST /api/kins/media` stores already-captured image data scoped to an existing account and Kin; images are deduplicated by SHA-256. `GET /api/kins/media?accountId=...&kinId=...&limit=20&offset=0` lists metadata, `GET /api/media/thumbnail?sha256=...` generates or returns a cached thumbnail, and `GET /api/media/blob?sha256=...` returns the authenticated image bytes. Gallery captures are identified as previews rather than originals. Source URLs are not stored. Thumbnails are a local derived cache and can be regenerated after import.
- `GET /api/digest`: total message, conversation, Kin, account and revision counts, legacy counts and latest archived time.
- `GET /api/conversations?accountId=...&kinId=...` and `GET /api/messages?accountId=...&kinId=...&conversationId=...` display records for one account and Kin. If both scope parameters are omitted, these endpoints instead show unassigned legacy data. A partially specified scope is rejected. `GET /api/search?q=...` searches scoped and legacy messages. Search is simple case-insensitive substring matching (SQLite's built-in case folding is ASCII-only) and returns at most 100 matches.
- Add `limit` (1–100) to `GET /api/messages` for a newest-first page, `total`, and `nextCursor`; supply that cursor to request the next older page. To jump directly to the oldest page, use `direction=oldest`; use `direction=newer` with the returned `newerCursor` to page back toward newer messages. Every page is returned newest-first, with a null cursor at either end. Cursors are scoped to the account, Kin, conversation, and direction. Requests without `limit`, `cursor`, or `direction` retain the original unpaginated behavior.
- `GET /api/download/portable`: stream a ZIP64-capable portable archive. `POST /api/import/portable` accepts `application/zip` and merges it atomically. The ZIP includes `manifest.json`, `README.txt`, `archive.sqlite3` (metadata only), and one `media/<sha256>.<extension>` per image. Database and image digests are checked on import. Unrecognized entries, duplicate names, unsupported schemas, damaged files, and invalid records are rejected. The current ZIP format is version 1; its SQLite schema is frozen by fingerprint, so future schema changes require an explicit format version and migration.
- `GET /api/download/sqlite`: stream a full SQLite online backup. `POST /api/restore/sqlite` accepts `application/vnd.sqlite3` and replaces the archive transactionally after schema, integrity, reference, and record validation. Before replacement, the server saves an online backup in the database volume's `backups` directory. Restore accepts SQLite backups with the current schema.
- `POST /api/download-ticket`: `{ "format": "portable" | "sqlite" }` returns an HTTP-only, same-site cookie valid for one matching browser download for two minutes; this permits the browser to stream directly to disk without placing the archive token in a URL. API clients can instead use the bearer token directly on the download endpoint.

Transfers stage files in a private temporary directory alongside the live database. Uploads are limited to 64 GiB, total expanded ZIP data to 128 GiB, images to 8 MiB, and ZIP entries to 500,000. They require sufficient free disk space; ZIPs and SQLite restores may temporarily consume several times the live archive size. Only one archive transfer may run at once. Downloads and backups are not encrypted. Store separate backups outside the Docker volume.

When an imported message has the same source ID but different content, it becomes the current message only if its `lastSeen` is valid and later than the current record's `lastSeen`. An older, equally dated, invalidly dated, or undated import is kept as a revision, preserving the existing current message. The import count reports that case as unchanged, even if a revision was added. Without a stable source ID, different fingerprints remain separate records because there is no reliable way to associate them.

Existing unassigned messages remain in their original tables without an inferred account or Kin; creating a matching account or Kin does not reassign them. Scoped conversations use a composite `(accountId, kinId, conversationId)` identity, so the same conversation and message IDs in different accounts do not collide. The synthetic conversation ID used for a Kin's observed messages does not imply that separate Kindroid sessions were identified.

The extension's page mapping determines what information can actually be captured. Messages not available to the observer cannot be archived.

Run `npm test` for deduplication, updates, import/export, authentication and host checks.
